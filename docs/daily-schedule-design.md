# 每日定时开关功能设计

状态：已实现（`oxygen_pump/oxygen_pump.ino` v2 固件，ESP8266 core 3.1.2 编译通过）

## 目标

在现有网页控制、PWM 调速和间歇循环的基础上，增加按每日时刻控制泵的功能。用户可以设置每天开始运行和停止运行的时间，并选择运行窗口内连续运行或按工作/休息时长循环。

示例：每天 17:00 开始运行，次日 08:00 停止。17:00 和 08:00 仅为示例默认值，用户应能在网页上分别修改开始与停止时刻并保存；时间值不写死在固件逻辑中。运行窗口内可连续运行，也可配置工作 5 分钟、休息 15 分钟循环。

本功能不需要增加时钟硬件，但要求 ESP8266 能连接家中 Wi-Fi 并通过 NTP 校时。

## 现状与限制

- 控制器目前只运行 Wi-Fi AP 热点，手机连接 `OxygenPump` 后访问 `192.168.4.1`。
- 自动模式使用 `millis()` 做相对计时，可以实现工作/休息循环，无法判断当前日期和时刻。
- ESP8266 没有可在断电后保持准确时间的硬件时钟。重启后必须重新从 NTP 获取时间。
- 设置保存在 EEPROM。增加设置字段时需要考虑旧固件数据兼容，不能假设 EEPROM 中已有新字段。

## 功能规则

### 每日运行窗口

- 在网页中分别设置每日“开始运行”和“停止运行”时刻，精度为分钟，输入范围 `00:00` 至 `23:59`；两项均可独立修改并持久化，不限定为示例时间。
- 开始时刻包含在运行窗口内，停止时刻不包含在运行窗口内。
- 停止时刻早于开始时刻表示窗口跨午夜。例如 `17:00` 至 `08:00` 表示当日 17:00 开始，次日 08:00 结束。
- 开始和停止时刻相同视为无效设置，网页应提示并拒绝保存，避免表达全天运行或全天停止的歧义。
- 运行窗口外始终停止泵，不受间歇周期影响。
- 每日计划有单独的启用开关。自动模式下关闭每日计划时，保留原有“上电/切换自动后按工作/休息分钟循环”的行为；启用后才按每日窗口控制。

### 运行窗口内的工作/休息循环

- 间歇循环提供启用/禁用开关。
- 禁用时，运行窗口内连续运行。
- 启用时，按“工作分钟”和“休息分钟”重复循环；两项均限制为 1 至 1440 分钟。
- 每个运行窗口开始时立即进入工作段，不先等待休息时长。
- 到每日停止时刻立即停止，即使工作段尚未完成。
- 新的一天到达开始时刻时重新从工作段开始，不延续前一天的循环相位。

### 模式优先级

沿用现有模式：自动、手动开、手动关。

- 自动模式由每日窗口及可选间歇循环共同决定泵状态。
- 自动模式且每日计划关闭时，继续使用固件现有的纯间歇循环逻辑。
- 手动开和手动关覆盖自动计划，并保持现有 EEPROM 持久化行为，直到用户再次选择自动模式。
- 选择自动模式后立即按当前本地时间计算状态；若尚未校时，则保持停止并显示等待时间同步。
- 修改速度时，如果泵当前处于运行状态，应立即应用新速度。

## 网络与时间方案

### Wi-Fi 模式

- 使用 ESP8266 的 AP+STA 模式：保留 `OxygenPump` 热点供手机本地控制，同时以 STA 模式连接家庭路由器。
- NTP 只用于校准设备时钟，不要求手机和控制器连接同一个网络，也不提供外网远程控制。
- 首期可用固件内配置的家庭 Wi-Fi SSID/密码；后续如有需要再增加网页配网。密码不应通过状态 API 返回，也不应写入日志。
- STA 连接失败时继续保留 AP 网页和手动控制能力，并周期性重连。

### NTP 与时区

- 使用 ESP8266 Arduino Core 的 SNTP/NTP 支持，通过 `configTime` 或对应系统时间接口配置 NTP 服务器。
- 默认使用中国标准时间 UTC+8，不启用夏令时。时区配置应集中定义，避免在时间计算中散落固定偏移。
- 推荐配置至少两个 NTP 服务器以提高可用性；系统时间有效后定期由 SNTP 校准。
- 判定时间有效前不能把系统启动时间或未初始化的 Unix 时间当作真实时间。
- 页面状态显示本地时间、时间同步状态和最后一次同步结果，便于用户判断自动计划是否可用。

## 断网、重启与异常行为

- **Wi-Fi/NTP 暂时断开但设备未重启**：使用当前运行中的系统时钟继续执行计划，STA 后台尝试重连并重新校时。
- **设备重启且暂时无法连接 NTP**：自动模式下保持泵停止，直到时间有效后再立即按当前时刻计算；手动模式仍可由用户操作。
- **NTP 首次同步发生在运行窗口中间**：自动模式按当前时刻进入正确状态。间歇循环从同步后开始新的工作段，避免推测断网期间已完成的周期。
- 设备应避免在时间无效期间反复开关泵，并在网页明确显示“等待时间同步”。
- NTP 服务器异常时不应阻塞 Web 请求或泵控制循环。

## 网页与接口设计

在现有控制页增加“每日计划”区域：

- 每日计划启用/关闭；关闭时自动模式沿用原有纯间歇循环。
- 每日开始运行时刻和停止运行时刻。
- 运行窗口内是否启用间歇循环；启用后显示工作分钟和休息分钟。
- 当前本地时间与时间同步状态。
- 现有速度滑块、手动开、手动关保留。

保存计划时由后端校验时间格式、边界和分钟范围。建议增加专用保存接口或扩展 `/set`，请求和响应统一使用结构化参数；现有 `/state` 增加计划配置及时间状态字段。接口不得暴露 Wi-Fi 密码。

API 具体字段名留待实现阶段确定。当前端点使用 GET 修改状态，增加计划保存时应考虑改用 POST，避免浏览器预取或缓存触发配置变更。

## 设置持久化与兼容

- 将每日开始/停止时刻、间歇循环开关和循环时长纳入设置结构。
- 保留现有速度与手动/自动模式含义，并给新增字段设置明确默认值。
- 固件升级需识别旧版 EEPROM 布局。建议为设置结构增加版本号或采用独立 magic/version 校验；发现旧布局时迁移已有速度、模式和工作/休息值，再写入新版本。
- 写入设置后检查并限制所有字段，避免 EEPROM 中损坏或旧数据导致无效时间、超长计时或异常状态。

建议出厂默认值：每日运行窗口 `17:00` 至 `08:00`，间歇循环关闭，工作/休息时长沿用现有已保存值。该时段只是可修改的初始值，不是固定限制；首次安装的默认值是否直接启用每日计划，需在实现前确定。为避免升级后自动改变用户当前行为，旧版 EEPROM 迁移时默认关闭每日计划，继续使用原自动循环行为。

## 状态计算建议

把“当前计划状态”作为纯逻辑计算：输入有效本地时间、每日计划开关、每日窗口、循环设置和手动模式，输出计划应开/关及当前阶段。硬件泵输出只由一个统一函数应用，避免 Web handler、计划判断和模式切换分别写 PWM 造成状态不一致。

时间窗口可转换为当天分钟数，并按是否跨午夜判断当前是否在运行区间。进入运行窗口时创建间歇周期的单调计时起点；如果设备首次校时已处于运行窗口内，则从校时完成时开始新的工作段。之后的阶段切换用 `millis()` 计时，窗口停止边界仍按本地时钟判断，避免 NTP 小幅校时造成工作/休息阶段跳变。

## 验收场景

1. 设置 `17:00` 开始、`08:00` 停止，验证 `16:59` 停、`17:00` 开、次日 `07:59` 按循环策略工作、`08:00` 停。
2. 设置同日窗口（如 `09:00` 至 `18:00`），验证开始包含、停止不包含。
3. 开启间歇循环，确认窗口开始时立即工作，工作/休息阶段按配置切换，窗口结束可截断工作段。
4. 关闭间歇循环，确认运行窗口内持续开泵。
5. 测试跨午夜窗口和同日窗口边界，以及开始等于停止时的输入拒绝。
6. 测试手动开/关覆盖计划、重启后模式恢复、切回自动后立即重新计算。
7. 测试 NTP 未同步、首次同步落在窗口内、运行中断网、重启时无网和网络恢复。
8. 使用旧版 EEPROM 设置升级，确认既有速度、模式和间歇配置没有被误读或清空。
9. 校验网页状态能区分泵状态、自动计划阶段和时间同步状态。

## 已确认决策（原「待确认事项」）

- 默认每日运行窗口采用示例 `17:00` 至 `08:00`；**新装与旧版升级均默认关闭每日计划**，升级后设备行为与旧固件完全一致，由用户手动开启。
- 家庭 Wi-Fi 凭据通过 `.env.local`（模板见 `.env.sample`，已被 git 忽略）维护，`scripts/flash.sh` 读取后生成 `oxygen_pump.ino.globals.h` 在编译期注入（ESP8266 core 会自动强制 include 该文件，Arduino IDE 与命令行行为一致）；留空则不连路由器，纯热点模式与旧固件一致。网页配网留待后续版本。
- 手动开跨重启保持（实现时修正了旧固件 `setup()` 无条件 `pump(false)` 导致手动开重启后不恢复运行的问题）。
- 时间未同步时自动模式保持停止，不提供强制运行入口，不在首期范围。

## 实现备注

- 设置结构 v2 更换 magic（`0xA5A5A5A5` → `0x5A5A5A5A`）；前 5 个字段与 v1 布局一致，迁移时直接沿用读出的速度/模式/间歇值，新增字段按上文默认值写入，所有字段入库前统一钳制。
- `/set` 同时注册 GET 与 POST：网页表单改用 POST 防浏览器预取误改配置，GET 保留兼容 curl 等直接调用。
- 泵输出统一由 `pump()` / `applySpeed()` 两个函数写入 PWM，Web handler 与计划状态机不再各自直接操作。
- Wi-Fi 凭据注入：`.env.local`（git 忽略）→ `scripts/flash.sh` 生成 `oxygen_pump.ino.globals.h`（git 忽略）→ core 编译期强制 include。固件源码中仅有 `#ifndef` 空默认值，凭据不会进入版本库。
- 同步状态经 `settimeofday_cb` 回调置位，并以 Unix 时间下限（2020-09）双重校验，未同步时 `/state` 返回 `sync:0` 且页面显示「等待时间同步」。
- 实现时顺带修复了旧固件自动循环中两个并列 `if` 的缺陷：当休息时长 ≤ 工作时长时，泵关掉后同轮立即重启，永不休息；现改为 `else if`。
